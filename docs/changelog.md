# 更新日志

本文件按版本记录可见变化；安装包与校验和见
[GitHub Releases](https://github.com/Coloryr/ModernMinecraftLauncher/releases)。

0.1.x 都是预发布版，标签带 `-pre` 后缀；界面上的「测试版 / 预发布版」徽章只表示构建通道。

## 0.1.8（开发中）

### 新增

- 手柄：固定按钮表以外的按键（高级手柄背面的拨片这类）在手柄图下方单独列出来，显示底层编号、
  按下时点亮；新出现的按键按第一次按下的顺序往后追加，松开后仍留在列表里。
- 启动前 / 启动后命令支持整行写法：一行里写「程序 + 参数」（`python.exe "%GAME_BASE_DIR%\update\updater.py"`），
  按空白拆词、双引号只用来分组；原来的「首行写程序名、之后每行一个参数」照旧可用。路径分隔符按平台统一，
  Windows 上 `/` 换成 `\`（词首的 `/c` 这类开关不动），其它平台 `\` 换成 `/`。
- 命令里的程序只写名字时依次在实例根目录、游戏目录、`PATH` 里找，`python.exe`、`cmd.exe`
  这类不必再写全路径；首词是脚本时按扩展名挑解释器：`.py` 用 Python、`.sh` 用 `sh`、
  `.ps1` 用 pwsh、`.bat` / `.cmd` 用 `cmd`，同一条命令在 Windows 与 Linux / macOS 上都能写。
- 崩溃分析认得 Forge 模组列表里的状态字母：被标成 Errored（状态含 `E`，如 `UCE`）的模组
  会单独给出一条结论，并排进「可疑模组」，不用再从异常栈里猜是哪个模组。
- 启动前 / 启动后命令在启动前先弹窗确认：列出这次会执行的命令，可选「执行 / 跳过 / 取消启动」，
  勾「不再提醒，直接执行」后不再询问；开关在设置 → 游戏启动页，默认开着。
- 新增 `mml-tools`：启动器自带的工具链统一放 `<启动器目录>/tools`。`.py` 命令需要 Python
  而本机没有时，Windows 自动把 python.org 嵌入式包下到 `tools/python`（整个启动器一份，
  换实例不用重下），下载任务显示为「Python 运行环境」。
- 启动设置与实例启动参数新增「加入 MML 环境变量」开关，默认开；关掉后不再向游戏进程传
  `MML_LAUNCHER` / `MML_LAUNCHER_VERSION` 与 `ARG_JAVA_LOCAL`、`ARG_GAME_DIR` 等 `ARG_*` 变量。
- 服务器实例的「基础文件」改成文件树：「全选」可整份带上，目录（含 `.minecraft`）
  能逐层展开，只勾其中的子目录也会整目录打进 `base.zip`；勾选状态与原来一样随实例保存。
- 服务器实例窗口新增「生成服务器包」「生成服务器包完整」两个按钮，不必先生成服务器实例，
  只要格式是 MML、填好发布地址即可导出。产物是可导入的
  MMC / Prism 实例包 zip（顶层 `<实例名>/`，含 `mmc-pack.json`、`instance.cfg`、`game.json` 与
  `mml-server-sync.jar`）。前者只带「基础文件」页勾选的内容，后者再加模组、配置目录、资源包等
  其余同步内容；两种包拖进 M²L 也会按 `game.json` 识别成实例包。MMC / Prism 侧靠 `instance.cfg`
  里的 `-javaagent:$INST_DIR/mml-server-sync.jar=<发布地址>/server.json` 同步，M²L 侧按 `game.json`
  的发布地址自己同步；包内还带实例图标，`game.json` 的 `Icon` 指向它。`mml-server-sync.jar` 已内嵌进
  exe，不用另外分发。
- 启动日志补上附加参数：附加 JVM 参数、附加游戏参数、附加 classpath 与传给游戏进程的环境变量
  各记一行，参数里的占位符已换成实际路径，排查启动问题时不用再回头翻实例设置。
- 启动日志在完整命令行前加一行「下面是实例启动参数：」，Java 路径后面不再直接接一整串参数。
- 启动日志补上文件检查阶段的明细：开始检查（版本 / 加载器）、游戏核心 / 资源文件 / 运行库 /
  整合包文件各多少、缺多少、自定义启动配置几份、启动主类、这次要下载几个文件、实际用的 Java
  版本。按设置关掉的检查项、资源索引还没下载、检查线程出错也各记一行，不再只剩一句用时。

### 修复

- MMC 导出的文件树原来以实例的 `.minecraft` 为根，看不到也不能勾实例根上的文件；现在与直接压缩
  一样以实例目录为根，默认勾上整份实例（`game.json` / `icon.png` 除外），`.minecraft` 外的文件
  按原位置进包。
- 导出 MMC 时自定义 JVM 参数原来完全没有写进 `instance.cfg`；现在会逐条写进 `JvmArgs`，并把
  `%GAME_BASE_DIR%` / `%GAME_DIR%` / `%JAVA_LOCAL%` 等换成 MMC 的 `$INST_DIR` /
  `$INST_MC_DIR` / `$INST_JAVA`（MMC 变量是单个 `$` 前缀，不带结尾 `$`）。
- MMC 导出补上实例图标：实例有图标时按原文件名放在包根，`instance.cfg` 的 `iconKey` 用文件名
  去掉扩展名（如 `gtnh_icon.png` → `gtnh_icon`），Prism / MultiMC 导入后能把图标装进自己的
  图标库，不再一直是默认图标。
- MMC 导出的 `instance.cfg` 按 MMC 的完整格式写：补上 `[General]`、`ConfigVersion`、各 Override
  与 ManagedPack 字段，不再只有 `InstanceType` / `name` / 内存几项；Prism / MultiMC 导入后
  设置能正常落位。
- 自定义 JVM 参数、游戏参数与附加 classpath 里的占位符（`%GAME_BASE_DIR%`、`%GAME_DIR%`、
  `%JAVA_LOCAL%` 等）原来原样交给 JVM，`-javaagent:%GAME_BASE_DIR%/mml-server-sync.jar=...`
  因为路径里带着 `%` 而找不到 agent 文件；现在与启动前 / 后命令走同一套替换。
- 替换占位符后，后面跟着的相对路径没有按平台换分隔符：Windows 上会拼出
  `\...\实例/mml-server-sync.jar` 这种混着两种斜杠的路径。现在只换占位符到 `=`、空白之间的那一截，
  同一个参数里的 URL（如 agent 的 `https://...`）不受影响。
- 手柄读取统一改用 SDL3，并开启后台事件读取；移除「XInput 兼容模式」开关与自建双后端合并逻辑。
  摇杆方向、扳机按钮与现有映射保持兼容；旧的 `gamepad/reader.json` 不再使用，也不会出现在映射列表里。
  SDL3 静态打包，运行时无需另装运行库。用 SDL3 而不是 SDL2：SDL2 自带版本在 Windows 上优先走 WGI，
  而 WGI 在窗口失去焦点时读数全为零，后台根本没输入；SDL3 的 Windows 后端只有 XInput 与 DirectInput，
  读写不依赖前台窗口。
- 肩键与扳机不再写反：LB / RB 记到 `LeftTrigger2` / `RightTrigger2`，扳机行程记到
  `LeftTrigger` / `RightTrigger` 并同步 `LeftZ` / `RightZ` 两个轴。
- 启动前 / 后命令整行被当成一个路径：`python.exe "x.py"` 这种写法直接报「路径不存在」，
  只写 `python.exe` 的名字也找不到程序，非得写全路径才行。
- `%GAME_BASE_DIR%` 原来替换成游戏目录 `.minecraft`，与包路径里同一个占位符的用法不一致；
  现在统一是实例根目录，`%GAME_DIR%` 仍是 `.minecraft`。
- 启动前 / 后命令会弹出一个空白控制台窗口并卡住：启动器是 GUI 进程，控制台程序（Python、bat）
  会自建一个空窗口，而命令的输出都走管道进了运行日志，窗口里什么都没有；脚本里的交互式提问
  又在那个看不见的窗口上等按键。现在命令以无窗口方式启动，stdin 接空设备。
- 启动前 / 后命令的输出不是实时的：Python 往管道写是块缓冲，整段日志要等进程退出才一次性出现。
  现在给命令补上 `PYTHONUNBUFFERED=1`；输出编码按实例的「日志编码」设置来，
  Python 拿 `PYTHONIOENCODING`，读回来也按同一套解，中文不会再整行当作非法数据丢掉。
- 启动前命令跑着的时候点「取消启动」不管用，得等它自己结束。现在会直接结束这条命令
  （Windows 上连带子进程），按取消处理，不再往下启动游戏。
- 命令输出一旦带颜色，之后追加的日志会整片被染成同一个色：Monaco 的装饰默认会跟着
  行尾输入一起变长，而日志追加正好插在最后一行的行尾。现在两种装饰都把粘性钉成
  「不随输入增长」，颜色只在它那一段里。
- 命令的 stdin 原来接空设备，Windows 上空设备算字符设备、`isatty()` 为真，脚本里的
  「按回车键退出…」照样会打印出来。改成接管道并立刻关掉写端，子进程读到的是 EOF。
- 「发现旧数据」弹窗里点「不导入」/「不迁移」后弹窗不收起，还得再点一次「关闭」；
  现在本机没有别的待答来源时点完就收起。
- 分组收起后顶部还钉着该组的粘滞标题；现在已收起的分组不再挂粘滞头，滚过下一组标题才换人。
- 占满窗口时实例卡片拖不动顺序，往上拖也不会自动滚动；现在按卡片左右半区算落点，
  拖到列表上下边缘都能自动滚。
- 双击标题栏最大化会把窗口关掉，下次启动还变成最大化；现在按下后移动超过 4px 才开始拖窗口，
  单击 / 双击都留在页面里处理。
- Java 26 不认 `-XX:+ZGenerational`，选 ZGC 或自动档直接起不来；现在只在 Java 21 / 22 补这个开关，
  23 起不再带，26 能正常启动。
- 自动 GC 不知道版本 JSON 已经带了 `-XX:+UseZGC`，又叠一套自己的；现在版本 / 加载器 /
  自定义参数里已有 GC 时自动档让位。
- 实例设置里换了 Java 有时不生效，以前填过自定义路径的实例会继续用旧路径；
  现在选具体 Java 或自动会清掉旧路径，取 Java 也以名字为准。
- 日志窗口的启动按钮在检查资源 / 下载阶段是禁用的，没法中途停；现在启动中再点一次
  就是取消启动，与主页面的取消口径一致。
- 导入压缩包时不再要求压缩包本身可写：从下载目录、只读位置或杀毒软件锁写的文件导入时，
  过去会报「读取压缩包内容失败（拒绝访问）」；现在探测与导入都按只读打开，只往实例目录写。
- 导入 HMCL 服务器包后转换为 MML 服务器实例：实例目录写出 `server.json`，
  清单里带地址的文件按 `fileApi` 下载并回写在线信息；同时修正 HMCL 清单的 `fileApi` 键名，
  导出的 HMCL 清单能被 HMCL 正常识别。

### 改进

- 服务器实例同步改为按包版本增量：只有 `PackVersion` 变化才替换文件，版本号没变时只保留本地清单；
  逐文件条目按 SHA1 比对，只补缺失 / 不一致的文件，旧清单里删掉的文件照样清理。
- 服务器实例的压缩包同步可以按目录选「删除原有目录」；不勾选时解压覆盖，服务端删掉的文件会留在客户端。
- 服务器实例同步会按清单里的 SHA1 判断配置压缩包是否变化：哈希没变时不重新下载 / 解压，
  只更新模组等真正变化的文件；目标目录被删掉时才补解压。
- 服务器实例窗口标题栏新增「指南」按钮；配置文件页的下拉文字改为居中，并移除两段旧提示。
- 服务器实例不能再生成服务器实例：右键入口置灰，实例下拉不列出，后端也会拒绝。生成成功会把
  格式、名字、版本、说明、网址、保存文件夹和编号映射一起写进 `server_instance_ids.json`，下次打开自动回填。
- 服务器实例的模组 / 资源包没有项目编号与文件编号时，会生成自定义编号并在清单里标记 `Custom`；
  自定义项目编号按 modid / 配置路径绑定并保存到实例根目录的 `server_instance_ids.json`，文件编号按内容更新；
  再次生成时变化的模组、资源包、配置目录会用黄色高亮。客户端不会把自定义编号当成 CurseForge / Modrinth 编号查询。
- 服务器实例的模组 / 资源包表格支持编辑项目编号、文件编号与下载地址，并显示本地文件 SHA1；
  新增「编号类型」下拉，可选在线 / 自定义，表格里不显示 custom- 前缀；已生成过的自定义项目编号锁定，
  新增条目才能改；资源包表改成与模组同款并继续使用虚拟列表。横向滚动到哈希列时行底边线补齐，
  配置同步方式下拉文字上下居中，全选 / 全不选按钮样式恢复。
- 基础文件勾选会随生成选项保存到 `server_instance_ids.json`，下次打开自动恢复。
- 服务器实例打开后就会按上次快照显示模组 / 资源包的新增 / 删除 / 修改数量（绿 / 红 / 黄），
  不必先生成；生成前调整勾选实时更新，生成后改用本次结果。新增行标 `+`、修改行标 `·`，
  删除的文件名列在红色汇总里；开始生成页也会显示这两组数量。
- 服务器实例窗口先读实例名 / 版本等元数据，再开始慢的模组扫描，输入框不再等目录扫描完才填。
- 自定义项目编号增加全局唯一校验：模组 / 资源包 / 配置共用编号表，手填重复直接拒绝生成；
  自动编号撞号追加后缀，旧映射里的重复项读取时自动修复。
- 服务器实例的配置目录可以单独选一级子目录（如 `config/setting`）：父包自动排除该子目录，
  子目录包按 `config.setting.zip` 命名并在父包之后解压；更深的目录不允许选。
- 服务器实例新增「基础文件」分组：可以勾选实例根目录下的文件或顶层目录（`.minecraft`、`libraries`、
  `patches` 等），打成固定的 `base.zip`；客户端只在第一次导入 / 同步时下载并解压到实例根目录，
  后续版本不会再次下载。实例图标仍单独输出为 `icon.png`，不进基础包。
- 新增独立服务器实例更新器 `mml-server-sync.jar`，供 PCL2 / HMCL / MultiMC 等非 MML 启动器
  在启动前同步 MML 的 `server.json`；支持增量下载、SHA1/SHA256 校验、
  旧文件清理、配置压缩包与基础包；既可命令行运行，也可通过
  `-javaagent:mml-server-sync.jar=<URL>` 在游戏 main 前执行，并自动识别 MML 启动器跳过。
  源码与用法见 [Coloryr/mml-server-sync](https://github.com/Coloryr/mml-server-sync)。
- 导入压缩包的类型「直接解压」改名「M²L 压缩包」；包内带 `game.json` 时优先按它识别，
  不会被 `manifest.json` 等其它启动器元数据抢走。
- Java 安装进度改用和整合包 / 资源下载同一套：标题栏上的 Java 指示器显示进行中数量与总进度，
  点开是安装任务弹窗，逐条显示「下载 / 解压 / 识别」阶段、进度与失败原因；多个版本可以同时装，
  关掉弹窗不影响后台继续安装。
- Java 下载窗口的标题栏也挂上了同一枚安装指示器（此前只在主窗口顶栏有）；判断「这个包在装」
  改成按包名比对，切换搜索源重新拉列表后同名的包不会又变回可点，前后端都拦一道。
- 下载器只负责把 Java 的 zip 拿到本地，解压单独成为一段（`mml_jvms::extract_java`），
  解压与 `java -version` 探测都放到阻塞线程池，探测另有 20 秒超时。
- Java 安装的解压与版本探测改到阻塞线程池执行，不再占住异步 worker（装大包时别的命令不会跟着卡）；
  `java -version` 探测加了 20 秒超时，扫描软件卡住 exe 时不会把整次安装挂死。
- 自定义主页添加新的接口，适配单窗口模式
- 所有实例下拉换成同一套带搜索与分组的选择器：实例多时按分组分节，输入即筛（名称 / 版本 /
  加载器 / 分组名都能搜），↑↓ 选、Enter 确认；主窗口列表模式、导出、生成服务器实例、
  设为实例图标、收藏安装、联机、统计、添加资源与设置里的实例锁定共用这一套。
- 手柄界面完善
- 手柄设置：手柄改成下拉选择并带「重新扫描」；外观按连接的手柄自动识别成 Xbox / PlayStation，
  认不出来时才显示手动选择；下拉项后面会带上识别结果。
- 手柄状态图加高重排，右摇杆不再压到面键；PlayStation 按自己的外形画（下方对称摇杆 + 中间触摸板），
  不再照搬 Xbox 的错开布局。图上不再画中间的 Guide 键，
  View / Menu 两颗画大了一档。
- 手柄按钮新增「模式」：普通是按下即按下、抬起即抬起；连续是点一次保持按下、再点一次松开；
  循环按下是按住期间按 120ms 间隔反复触发。旧配置没有 Mode 字段时按普通处理。
- 手柄设置的轴映射下面多了一条区间条：把 -1.0 到 1.0 画成一条，标出这条绑定覆盖的区间与摇杆
  当前值，读数落在区间里时整条高亮，调区间不用再对着数字猜。
- 手柄设置新增「启用游戏内手柄」开关（默认关）：关着时只预览、不向游戏发送任何输入；
  打开后会提示需要在游戏里装好并启用 coloryrasm，手柄输入才会生效。配置项是 `Enable`。
- 客户端设置的「游戏标题」也加了同样的提示：开了自定义 / 随机 / 循环标题后，提示需要在游戏里
  启用 coloryrasm 才会生效；两处共用 `.tip-note` 一条样式。
- 手柄映射的输出支持组合键：动作写成 `LeftAlt+E` 这样的顺序，按下按书写顺序发、松开按反序发，
  同一个键被多条规则按住时只发一次按下，松开计数归零才发抬起。
- 手柄设置：输出动作不再用下拉。点开是一张按真实键盘排的图（Esc / F1-F12、数字行、QWERTY、
  空格与修饰键，右侧编辑键、方向键与鼠标滚轮）。先点修饰键再点主键就是组合输出，存成
  `LeftAlt+E` 这样的顺序，芯片上显示「Alt + E」；键盘键也能直接按物理键选中，
  后端不支持的键画成灰色占位，保证键盘形状不变。标点、CapsLock、Win、Menu 这些键也能绑了，
  动作表里补了 Grave / Minus / Equal / LeftBracket / RightBracket / Backslash / Semicolon /
  Apostrophe / Comma / Period / Slash / CapsLock / LeftSuper / Menu。
  弹窗打开时键盘只用来记录：按键不会触发弹窗里的按钮、也不会顺带把面板关掉，改完点「确定」才写回。
- 手柄设置：按键映射改成左右两列，各占一半。左边挑手柄按键，点开是面板上那张实时手柄图：
  打开时先记下已经按住的键，之后每按一颗追加到顺序里，下方按顺序排出「LT → ←」，第一颗当修饰键、
  最后一颗当主键，图上也能直接点选。右边挑键鼠输出，点开是键盘 + 鼠标的简易图，键盘键可以直接按
  物理键选中，鼠标与滚轮点选；原来的动作下拉与 ActionSelect 组件一起删掉。弹窗右上角不再画 ✕。
- 启动前 / 后命令的工作目录从 `.minecraft` 改成实例根目录，与双击整合包里的 bat 一致：
  命令里可以照 bat 写相对路径，游戏目录用 `%GAME_DIR%` 取。
- 日志窗口支持命令输出里的 ANSI 颜色：显示前剥掉 `ESC[96m` 这类转义，按 16 色还原前景色，
  粗体 / 变暗 / 下划线也认；256 色与真彩色不还原，只把转义去掉。复制出来的正文不带转义。

  升级期间不能退出启动器，完成后发一条系统通知。
- 资源管理：模组依赖关系图改为占满窗口的子页面，用返回键或 Esc 回到模组列表。

### 改进

- 下载索引改用嵌入式事务库，旧版 `mod_download.json` / `resourcepack_download.json`
  在启动时自动导入并留底，不再整份重写 JSON，崩溃不会留下半截文件。
- 索引查询从「整表加载进内存」改为按键点查：按文件哈希找公共文件、按项目取最近版本都是点查，
  启动不再整表读取。
- 索引写入按批次提交，不再每条记录一次 fsync；存量映射每处理完一个实例落一次盘。
- 存量资源映射会跳过已经映射过的文件，中断后重开可以接着处理，不必重新校验整份哈希。
- 设置「本地文件」的占用统计改用实例的映射记录判断硬链接，不再逐文件打开句柄，大实例从几分钟降到秒级。
- 下载窗口改成 100ms 刷新，进度条与线程行更跟手；下载进度事件按线程限流到 10Hz，
  几千个小文件的下载不再让界面跟着事件风暴重渲染。
- 下载完成的系统通知只报「N 个下载任务已结束」，不再带「打开下载窗口查看结果」。
- 模组「更新记录」弹窗改成不带框的列表：记录之间只有一条分界线，版本跃迁、文件名、
  文件号与 SHA1 各占一行，长版本号不再把文件名挤成一列竖排。
- 切换单窗口 / 多窗口不再重启启动器、也不重载界面：只关掉主窗口以外的窗口就地切换，
  游戏在跑的时候也能切换，不会闪一下原生标题栏。
- 同一台机器上放了两份启动器时不再被任务栏并成一个按钮：任务栏身份按运行目录区分，
  不再受开始菜单里残留的快捷方式影响。
- 系统通知不再依赖开始菜单快捷方式：通知身份改为登记进注册表，便携版与多份安装都不必再往
  开始菜单塞文件，也不会互相覆盖。

### 修复

- 资源映射进行中关闭设置页不再被拦下，关闭启动器仍会拒绝并给出提示。
- 进度条总数为 0 时改为无限滚动，不再显示一条静止的空进度条。
- 启动前检查只修复已经映射过的文件，不再自动把未映射的实例文件搬进公共目录（改由设置里手动执行）。
- 客户端设置锁不再跨安装共用：内部数据目录那份锁文件按运行目录区分，同一台机器上的几个启动器
  各锁各的，不会因为一个上了锁就把另一个也锁上，也不会互相删掉对方的锁。
- 修复下载完成瞬间整个程序无响应：任务收尾时在持锁状态下回调界面，与主线程的下载状态查询互相等待。
- 修复下载过程中界面卡顿、输入无响应：每收到一条下载进度事件就整份拉一次状态，
  几千个小文件时把主线程压满。
- 修复 Apple Silicon 上 GTNH / 1.7.10 整合包点启动就失败：MMC 补丁里平台写在构件名中的
  原生库（如 `org.lwjgl:lwjgl-natives-macos:3.4.3`）被当成三段坐标解析，游戏启动线程异常退出。
- 修复 `osx-arm64` / `windows-arm64` 这类带架构后缀的启动规则不生效：arm64 原生库被当成
  系统不匹配滤掉，启动游戏时会缺对应的动态库；多条 `allow` 规则现在按任一命中处理。
- 修复 GTNH（lwjgl3ify）在 macOS 上 SDL 初始化失败 `No available video device`：
  MMC 的 `FirstThreadOnMacOS` 特性现在会转成 JVM 参数 `-XstartOnFirstThread`。
- 修复macos下的无法拖拽导入
- 打开文件夹 / 打开网址不再闪一个命令行窗口：改成调系统外壳（ShellExecuteW），不再经 cmd 启动。
- 日志窗口的「测试启动」按钮跟着实例走：主窗口点的启动，检查文件那几段在这里也会置灰并显示
  阶段；进程起来后按钮换成「停止」，与主窗口同一口径。
- 单窗口模式下拖入文件只由一个页面处理：切走的页面被缓存后仍在接拖放，拖一个 jar 进模组列表会
  在「已导入」之后再弹一句「不支持的文件类型」。
- 从模组依赖图返回列表时滚回原来的位置，不再跳回开头。
- 模组工具条的「导出模组列表」换了图标：原来那颗「托盘 + 向上箭头」紧挨着「检查更新」的
  向上箭头，两个都读作往上，现在是一页纸 + 从纸角送出去的箭头。
- 资源管理标题栏的「添加资源」入口换了图标与提示：原先和紧挨着的下载指示器都画向下箭头，
  现在换成加号，提示文字改成「添加资源」。
