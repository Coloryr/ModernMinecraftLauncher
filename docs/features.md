## 0. 概览

M²L 是一个 Minecraft 启动器：内核 `mml-core/`（Rust workspace，18 个子 crate）+ 桌面壳
`mml-gui/`（Tauri 2）+ 前端 `mml-vue/`（Vue 3 + Vite）。合计 **250 个 IPC 命令 / 38 个跨窗口事件**。

窗口一览（`mml-vue/src/windows/registry.ts`）：

| 窗口 | 说明 |
| --- | --- |
| 主界面 | 实例列表 / 分组 / 启动 / 主页（新闻、快捷启动） |
| 添加实例 | 新建、压缩包、文件夹、在线地址四种导入方式 |
| 导出实例 | 导出成 CurseForge / Modrinth / MMC / HMCL 整合包 |
| 资源管理 | 模组 / 存档 / 材质包 / 截图 / 服务器 / 光影 / 结构（含数据包子页） |
| 添加资源 | 在线搜索并下载模组、材质包、光影、存档、数据包 |
| 下载整合包 | 按 CurseForge / Modrinth 项目安装整合包并建实例 |
| 资源收藏 | 收藏的项目、分组、一键下载 |
| 账户管理 | 六种账户、皮肤与披风、登录方式锁定 |
| 配置文件 | 编辑 options.txt / config / kubejs / local / 存档内的文件 |
| 游戏日志 | 实时与历史日志、筛选、上传 mclo.gs |
| 方块列表 | 从客户端 jar 离线渲染方块与物品图标 |
| 下载管理 | 下载任务与线程的进度、暂停、取消 |
| 下载 Java | 从四个发行方站点挑版本下载 |
| 启动器设置 | 界面 / Java / 网络与下载 / 游戏启动 / 皮肤与头像 / 客户端 / 本地文件 / 实验性功能 |
| 游戏统计 | 实例数、启动次数、游戏时长 |
| 帮助手册 | FAQ、开源许可、第三方服务 |

单窗口模式下这些窗口变成应用内页面（工具型窗口改以悬浮弹窗出现）。

### 0.1 目录与配置文件

启动器运行目录（`mml_base::get_base_dir()`；默认 Windows 是程序同级的 `mml/`，Linux 是 `~/.mml/`，
macOS 是 `/Users/shared/mml/`；发布版可用数据目录里的 `run` 文件改）：

| 路径 | 内容 |
| --- | --- |
| `minecraft/` | 游戏数据根：`versions/`（版本 json 与核心）、`libraries/`（运行库）、`assets/`（资源索引与 objects）、`instances/`（实例） |
| `java/` | 下载的 Java 运行时 |
| `cache/` | 下载缓存与 WebView2 数据目录 `cache/webview`（启动时清缓存会跳过 `webview/`） |
| `logs.log` | 启动器运行日志 |
| `gui_config.json` | GUI 配置：主题、语言、窗口模式、背景图、客户端设置、登录方式锁定等 |
| `window_save.json` | 各窗口几何（位置 / 大小 / 最大化），键是窗口 uuid（含每个实例的族窗口） |
| `config.json` | 内核配置：下载源与线程数、代理、DNS、检查与 SHA1 开关、游戏启动默认参数等 |
| `collect.json` | 资源收藏（条目与分组） |
| `block_groups.json` | 方块列表的自建分组、收藏与左栏顺序 |
| `group_save.json` | 实例分组；启动时会把旧版 `instgroups.json` 并入并删除旧文件 |
| `count.dat` | 游戏统计（NBT；见 [§15](#15-游戏统计)） |
| `block.json` / `items.json` | 方块与物品图标的渲染结果与版本号 |
| `server.json` / `server.old.json` | 服务器包的远端清单与上一次的清单（按实例） |
| `colormc_migrate.json` | 从 ColorMC 迁移的选择（删除它可重新触发迁移询问） |
| `custom_ui/` | 自定义 CSS 包 `css/<id>.zip` 与整页包 `page.zip`；由 `mml-ui` 协议按条目现读，不解压 |

实例目录 `minecraft/instances/<名字>/`：

| 路径 | 内容 |
| --- | --- |
| `game.json` | 实例设置（版本、加载器、启动参数、窗口、整合包来源…） |
| `gui_setting.json` | 实例的界面设置：模组分组与备注、资源窗口视图偏好、日志窗口设置 |
| `.minecraft/` | 游戏目录（`mods` / `config` / `saves` / `screenshots` / `resourcepacks` / `shaderpacks` / `schematics` / `logs` / `crash-reports` / `kubejs` / `local`、`options.txt`、`servers.dat`） |
| `backup/` | 存档备份 zip 与 `save_backups.json` 索引 |
| `cache/`、`temp/` | 实例级缓存与临时目录 |
| `json/` | 自定义启动配置（自定义 json / MMC 模式） |
| `libraries/` | 自定义加载器的库 |
| `modfileinfo.json` | 资源（模组等）信息与在线来源标记 |
| `mod_update.json` | 模组更新记录（项目号、版本 / 文件号变更历史） |
| `launch.json` | 实例启动统计 |
| `icon.png` | 实例图标 |
| `loader.jar` | 自定义加载器 jar |
| `log4j-rce-patch.xml` | Log4j 补丁（需要时生成） |

## 1. 实例管理（主界面）

- 实例列表三种视图：**分组 / 平铺 / 列表**（设置里切换）；侧栏可收起、可左右换边。
- 侧栏搜索（名字 / 版本）、分组折叠、运行中的实例带小圆点。
- **添加分组**；实例可**拖拽跨组移动与组内排序**，分组标题本身也可拖动重排。
- 右键菜单：实例（启动 / 打开文件夹 / 查看日志 / 修改配置文件 / 选择图片改图标 / 重命名 / 删除）、
  分组（全选 / 启动全部 / 转移分组 / 删除分组，默认分组不可删）、多选（修改分组 / 删除 / 启动全部）。
- **多选模式**：批量修改分组、批量删除（带总进度）、批量启动。
- 单个实例：启动、停止、重命名（实例目录一起改，重名拒绝）、删除（进回收站）、打开实例目录、
  改图标（系统选图 → 裁剪）。
- 详情区：实例设置（元信息 + 启动参数）、自定义执行、自定义 JSON（`json/` 目录）、
  自定义服务器（地址 + 启动时加入 + MOTD）、游戏内代理、内存提示、游玩时长、MOTD 卡；
  整合包实例另有「检查更新」入口。
- 顶栏：账户选择器、设置 / 统计 / 收藏 / 帮助四个入口、三个任务指示器（整合包安装 / 下载 / 资源下载）、
  自定义音乐入口（配了音乐来源才出现）、自绘标题栏（Windows / macOS 两套按钮）。
- **启动器主页**：Mojang 官方新闻列表（分页、打开原文）、空实例引导块、上次游玩快捷启动；
  可在设置里选"启动后停在主页还是项目列表"。
- 拖入文件分流：网页卡片 / 登录快捷方式 → 账户窗口；整合包 / 文件夹 → 添加实例窗口。
- **实例锁定**（设置里可开）：只能操作被锁定的那个实例，列表强制切到列表视图；
  锁定实例被删则整块换成错误页。

## 2. 添加实例

四种模式：

| 模式 | 能力 |
| --- | --- |
| 新建 | 选版本类型 → 游戏版本 → 加载器 → 加载器版本（自定义加载器选本地 jar） |
| 压缩包导入 | 选 zip → 自动探测包类型并预填 → 可选包内文件 → 导入 |
| 文件夹导入 | 选目录 → 扫描（可识别出多个实例）→ 勾选要导入的 → 导入 |
| 在线地址 | 填整合包下载 URL → 下载安装 |

- 导入来源共 **7 种包类型**：CurseForge、Modrinth、MMC/MultiMC/Prism、HMCL、HMCL 服务器包、
  本启动器导出的实例包、其它启动器的 `.minecraft` 目录包（自动判版本隔离并挑主版本）。
- 分组可现建；重名弹窗（覆盖 / 改名）；导入进度弹窗；导入中拦窗口关闭；可取消。

## 3. 导出实例

- 四种格式：**CurseForge / Modrinth(.mrpack) / MMC / HMCL**。
- 三个页签：整合包信息（包名 / 作者 / 版本号 / 简介）、模组勾选（带在线来源标记 + 搜索 + 全选）、
  文件与目录勾选（文件树懒加载）。
- 每个文件可单独填下载地址（仅 Modrinth 生效）；默认勾选 `config` / `resourcepacks` / `shaderpacks`。
- 另存为对话框，后缀按格式给 zip / mrpack；逐文件进度；同一时刻只允许一个导出任务。
- 自定义加载器在 MMC / HMCL 下会丢失，界面有警告。

## 4. 启动、版本与加载器

- **支持的加载器 9 种**：原版、Forge、Fabric、Quilt、NeoForge、OptiFine、LiteLoader、自定义（本地 jar）、
  Cleanroom（1.12.2 的 Forge 分支，安装器与 universal 包从 CleanroomMC 官方源取）。
- 某游戏版本支持哪些加载器、以及各加载器的版本列表都在添加实例窗口里即时查询（带刷新）。
- 启动流程：清上次日志 → 三项前置检查（版本号 / 加载器版本 / 自定义 jar 存在）→ 按类型刷新账户 →
  （服务器包类实例）检查并同步服务器包 → 文件完整性检查并自动补齐（核心 jar、资源 objects、
  运行库、整合包 mod，各自可开 SHA1 校验）→ 选 Java → 组装 JVM 参数与游戏参数 → 替换占位符 →
  拉起进程 → 执行后置命令。
- **JVM 参数**：`-Xms/-Xmx`、GC 模式（Auto 按 Java 版本选 ZGC / G1GC、也可指定或自定义）、
  ColorASM 彩色日志 javaagent、外置登录 javaagent（Nide8 / AuthlibInjector / LittleSkin / 自建）、
  自定义 JVM 参数与环境变量、附加 classpath、自定义主类。
- **游戏参数**：全屏或指定宽高、自动进入存档 / 服务器（1.20+ 用 `--quickPlayMultiplayer`）、
  游戏内代理、自定义游戏参数。
- 启动前 / 启动后命令（支持 `%JAVA_LOCAL%` / `%GAME_DIR%` / `%GAME_NAME%` / `%JAVA_ARG%`
  等占位符，可选择与游戏同时运行）。
- 账户令牌在启动前按类型刷新，失败会询问是否降级为离线；启动日志里 uuid / accessToken 打码。
- 每次启动用独立线程与独立运行时；**不同实例可同时运行**，同一实例不允许重复启动。
- 目录结构：`<运行目录>/minecraft/{versions,libraries,assets,instances}`，
  实例目录 `<instances>/<名字>/`，实例配置 `game.json`，游戏目录 `<实例>/.minecraft`；
  `versions` / `libraries` / `assets` 全局共享，其余按实例隔离。
- **服务器包同步**：`serverpack` 类型实例在启动时按远端 `server.json` 比对 SHA1 后增删文件。

## 5. 资源管理

**一个实例一个窗口**（打开时锁定实例，窗口内不再切换）。左侧 7 个分类，存档下另有数据包子页；
分类顺序可拖拽、记住上次打开的分类。列表刷新、切分类不重读、删除进回收站、
模组扫描带进度条、多选（勾选 / Shift 整段选）、批量操作、拖放导入。

### 5.1 模组

- 解析 jar 元数据（Forge toml/json、Fabric、Quilt、mcmod、MANIFEST core 标记）、图标、
  jar-in-jar 内置模组树、加载侧（client/server）、下载来源（CF / Modrinth）。
- **列表 / 表格两种视图**；表格 14 列、列宽可拖（落盘）、表头点排序。
- 启用 / 禁用（只改文件名后缀）、删除、打开文件夹、**备注**（右键弹窗或表格内就地编辑）。
- 搜索（名字 / modid / 文件名 / 作者 / 版本 / 简介）。
- **自定义分组**：新建 / 重命名 / 删除；一个模组同时只属一个组，移进分组会顺带启用；
  分组块可折叠、可拖拽排序（含"识别失败 / 已启用 / 已禁用"三个固定分组）。
- 分组右键菜单：启用所有 / 禁用所有 / 转移内容 / 移除分组 / 删除所有模组。
- **依赖检测**：检查各包声明的强制前置是否齐全、版本是否满足，列出**缺少前置 / 前置被禁用 /
  版本不符**三类问题（缺的排最前）。加载器与游戏自身提供的前置会跳过
  （如 Forge 实例里的 `forge` / `minecraft`），内置 jar-in-jar 里的模组算"已提供"，
  只有启用状态的模组参与检测。要重扫一遍模组，跑的时候按钮置灰。
- **依赖图**：单个模组的右键「依赖图」按后端算好的节点 / 连线画图，必装与可选前置分色，
  游戏 / 加载器画成虚拟节点，能看出循环依赖；双击节点换成以它为目标，点连线说明这条关系，
  可重置视图。
- **启用 / 禁用的连带处理**：禁用被别的模组依赖的项时问「一起禁用」；启用缺前置的项时问
  「一起启用」，避免手动逐个找。
- **重复安装检测**：同一 modid 有多个文件同时启用时单独列出（`modid 重复` 分组）；
  检查出更新的模组也会归到 `有更新` 分组。
- **更新检查**：按在线信息逐个项目查新文件，结果弹窗按「当前 → 最新」列出并默认全勾；
  下载更新会下新文件替换旧文件（旧文件进回收站，下载失败保留原文件），查询失败的个数会如实说明。
- **替换版本**：单个模组可换成平台上同一项目的其它版本；**更新记录**按项目留一条
  「版本 / 文件号」变更历史，可筛选、可删。
- **自动标记**：按 jar 的 SHA512 去 Modrinth 反查项目并写回在线信息，可选是否覆盖已有条目。
- 批量：启用、禁用、移到分组、删除。

### 5.2 存档

- 解析 `level.dat`：显示名 / 上次游玩 / 模式 / 难度 / 极限 / 种子 / 图标 / 损坏标记 / 备份数。
- **编辑存档**：名字、游戏模式、难度、极限模式、种子（i64 校验 + 随机）；实例运行中直接拒绝。
- **备份 / 还原**：备份 zip 到实例 `backup/` 并登记索引；还原前二次确认，旧存档先移入回收站。
- 单行菜单：编辑 / 修改配置文件（跳配置文件窗口并落到该存档）/ 备份 / 还原 / 打开文件夹 / 删除。
- 批量只有删除。存档名支持 `§` 格式码显示。

### 5.3 数据包（存档子页）

- 落点 `saves/<存档目录名>/datapacks`；需先选存档。
- 解析 `pack.mcmeta`，启用状态取自 `level.dat` 的 `DataPacks.Enabled/Disabled`。
- 启用 / 禁用 / 删除（删除会先清 `level.dat` 引用）、批量三种操作、打开数据包目录。

### 5.4 材质包

- 解析 `pack.mcmeta`（简介按界面语言查包内语言表、min/max_format、`pack.png` 图标）。
- 启用 / 禁用、删除、打开文件夹；批量启用 / 禁用 / 删除。
- ⚠️ 启用/禁用目前**写错文件**，见 [§20](#20-疑似缺陷待实机确认)。

### 5.5 光影

- 解析 zip / 目录里的 `lang/*.lang` 取名字与说明；当前光影由 `options.txt` 的 `shaderPack` 判定。
- 设为当前光影 / 取消（点已选中的那个即取消，写 `OFF`）、删除、打开文件夹；批量只有删除。

### 5.6 结构文件

- 支持 `.schematic` / `.litematic` / `.schem`（WorldEdit）/ `.nbt`（Create）。
- 列表显示名字 / 作者 / 描述 / 尺寸 / 方块总数 / 种类数；**详情**按方块种类计数排序（只读）。
- 删除、批量删除、打开文件夹。

### 5.7 截图

- 网格 + 大图预览（滚轮缩放、放大后拖动平移、点空白或 Esc 关闭）。
- 单张删除、批量删除、清空全部（都进回收站）；预览走 `mml-image` 协议。
- 单张「复制图片」把原图写进系统剪贴板。

### 5.8 服务器列表

- 读写 `servers.dat`（NBT）：添加、编辑（名字 / 地址 / 接受材质）、删除。
- 进分类时**并发**查询所有服务器 MOTD（含 SRV 解析），行内显示能否连上、在线人数徽标。
- 列表上方一张 MOTD 卡显示选中的那台，可单独刷新；行图标用查询回的 favicon。
- 服务器列表可整份**导出 / 导入**：导出复制 `servers.dat`；导入先备份、再替换并解析校验，失败会还原。
- 批量只有删除。

### 5.9 拖放导入

- 资源窗口**只接文件**：目录、纯文本 / 网页卡片在悬停阶段就不放行；松手后再用后端探测过滤一次。
- 落点 = 当前面板对应的目录；数据包页落到所选存档的 `datapacks`。
- 同名冲突"每次问我"：预检 → 弹窗选**跳过 / 重命名 / 覆盖** → 落盘；存档包按目录名解压（重命名加 ` (1)`）。
- 同一套拖放也用在主界面、添加实例、账户窗口。

## 8. Java 运行时

- **扫描本机 Java**：Windows 走 `where javaw.exe` + 注册表（JavaSoft JRE / JDK、Eclipse Adoptium、
  Azul Zulu）+ 常见目录；Linux 走 `which` + `update-alternatives` / `pacman` + 常见目录；
  macOS 走 `/usr/libexec/java_home` + `/Library/Java/JavaVirtualMachines`。
  判定靠执行 `java -version` 解析版本与位数。
- 管理：手动添加（选 exe 后探测名字）、全机扫描、扫描指定目录（含子目录）、
  从压缩包导入（zip / 7z / gz / tar，带解包进度）、删除单个 / 全部。
- **下载 Java**：四个源 —— Adoptium、Zulu、OpenJ9、Foojay；可选 JDK / JRE、
  主版本、系统、架构；产物为 zip / tar.gz 归档，下载后自动解包并识别注册。
- 版本匹配：过滤架构、精确或 ≥ 指定版本，降序取最高。

## 9. 下载管理

- 并发数可配（1–64，默认 10）；**断点续传**（按 `Accept-Ranges` 决定，重试用 Range 续写）。
- **哈希校验**：MD5 / SHA1 / SHA256 / SHA512 / SHA1+SHA256 / SHA1+SHA512；
  上游没公布哈希（空值）时跳过；另校验字节数与 `Content-Length`。
- 单文件累计失败超过 5 次放弃并删残缺文件；取消不计入失败数。
- **全局**暂停 / 继续 / 取消（单任务级见 [§19](#19-未接线--半成品)）。
- 界面：总览（任务数 / 文件数 / 已下字节 / 总速度 / 总进度条）、任务列表（状态、文件数、失败数、
  大小、已进行时间、进度条）、线程列表（文件名、进度、大小、速度、状态）。
- 任务全部结束且无失败时自动关窗；单窗口模式下是悬浮弹窗，关掉不影响后台下载。
- 下载后处理：解压 native 库、解压存档 zip。

## 10. 配置文件编辑

- **文件范围**：实例的 `options.txt` 与 `config/` / `kubejs/` / `local/`，或某个存档目录下的全部文件
  （含数据包、`level.dat`、区域文件）。路径一律"相对所选来源"，并挡路径穿越。
- **按扩展名认类型**：json / json5 / toml / yaml / properties / xml / javascript / snbt / **NBT**
  （dat / dat_old / rio / nbt）/ **区域文件 mca** / **图片** / 压缩包 / 其余按纯文本。
- **五种视图**：

  | 视图 | 能力 | 可保存 |
  | --- | --- | --- |
  | 文本 | Monaco 编辑，按语言着色 | ✅ 行级差异 |
  | NBT | 树形：改标量 / 新增（12 种类型）/ 改名 / 删除；数组按下标 | ✅ 会话内套改动 |
  | 区域文件 `.mca` | 区块表（下标 / X / Z / 扇区偏移 / 占用 / 时间戳），只读文件头；可按坐标 / id 查找方块实体与实体 | ❌ |
  | 图片 | 直接显示（上限 4 MiB） | ❌ |
  | 二进制 | 十六进制分页（单页 64 KiB） | ❌ |

- **保存校验**：文本走行级差异 + 前端自检 + 后端基准 SHA1 核对；NBT 在打开时的句柄上写回，
  写前核对 SHA1 与文件的 mtime / 长度，只成功一半就丢弃会话。
- 上限：文本与 NBT 树 4 MiB；NBT 数组最多 1024 个元素可展开 / 增删。
- 文件树可搜索、目录可展开、命中目录自动展开；有未保存改动时提示并让保存键转强调色。
  保存入口是右上角的保存按钮，也可以按 `Ctrl+S` / `Cmd+S`（与按钮同一条件：有改动且未在保存中）；
  `.mca` 页的「查找」会扫存档内的区域文件，命中后切到对应文件并翻到那一块。

## 11. 游戏日志

- **一个实例一个窗口**。
- 实时日志（订阅 `game-log`，按实例过滤，内存上限 10000 行）与历史日志
  （实例 `logs` 与 `crash-reports`，只接受列表内的路径）。
- 筛选：5 个等级开关（Info / Warn / Error / Debug / 其它）、线程下拉、分组下拉；换行与自动下拉开关；
  页内查找（Monaco 查找框）。
- 设置持久化到实例的 `gui_setting.json`；换行是**全局**偏好（与配置编辑器共用，Alt+Z 可切）。

- 异常退出（退出码 ≠ 0）自动打开该实例的日志窗口：2 分钟内生成过崩溃报告就打开最新那份，

  其余结论折在「其它发现」里，可一键关掉。
- **测试启动 / 停止**：可直接从日志窗口拉起或结束该实例。

## 12. 方块与物品图标

  按条目现读），页面内可用 `window.mml` 调命令与订阅 5 个白名单事件；可开 / 关 / 删除。
- **自定义 CSS**：可装多份 zip（包根 `custom.css`，可选 `custom.js`），按条目启用 / 排序 / 删除；
  样式与包内静态资源走 `mml-ui` 协议现读；入口脚本可改文字 / 类名，也能换成 Vue 组件。
- **完全自定义界面**：装一份 `page.zip`（`index.html` 或 `custom.js`），整页替换主窗口，
  也能按 kind 替换任意窗口组件；关包或页面挂掉时回落到内置界面。
- **自定义音乐**：本地音频或 http(s) 直链，标题栏出现播放 / 暂停 / 停止入口。
- **窗口外观**：材质（自动 / Mica / Acrylic / 无）与底色不透明度，由系统在窗口背后合成。
- 背景图支持本地文件与网址，后端缩放后下发；有背景时界面表面半透明。
- **一个实例一个窗口的窗口族**：日志 / 资源管理 / 添加资源 / 配置文件四族的窗口身份由实例 uuid
  派生，同一实例重复打开只聚焦。
- 窗口几何存在 `window_save.json`，按窗口（含每个实例的族窗口）恢复位置、大小、最大化。

## 15. 游戏统计

- 窗口：三张汇总卡（实例数 / 总启动次数 / 总游戏时长）+ 每实例表格（启动次数 / 时长 / 最近游玩），
  运行中每 5 秒刷新；已删除的实例保留历史。
- **记录侧**：`mml_game::game_count` 在 `mml_core::load` 之后初始化（`lib.rs`），进程起来时记一次
  启动（`launch_done`）、失败记 `launch_error`、退出记 `game_close`，数据落 `count.dat`。
- **计时**：每一局存起止时间；后台线程每 100ms 把时长累加进全局总时长与实例累计时长，
  **与界面是否打开无关**。统计窗口里正在运行的那一行按「开始时间 → 现在」现算，所以会自己往上走。
- 主界面详情区的「游玩 X 小时」是累计值，只在拉取时刷新（挂载、游戏退出后）。
- **关窗后台计时**：主窗口关掉后 webview 销毁、进程留在托盘，计时线程照常跑，运行中的游戏继续累计；
  托盘图标或再启动一次 exe 都能把界面唤回来，见 [§18](#18-其它)。

## 16. 数据迁移

- **支持从 ColorMC 迁移**：启动时探测 ColorMC 工作目录（记路径的文件 → 平台默认位置 → `%APPDATA%`），
  首次启动问一次（复制 / 移动 / 不迁移，可跳过，删掉标记文件可重新触发）。
- 迁移方式是**顶层条目原样复制或移动**（不做字段级转换）；移动同盘瞬时，跨盘回退复制 + 删源；
  单文件失败不中断；搬完做兼容性检测（逐条 `ok` / `partial` / `extra` 结论 + 逐个实例用本启动器的
  解析器验读 `game.json`），并提示哪些数据不会被沿用、账户文件永不迁移。
- HMCL / MMC / 官方启动器的数据**没有专门的迁移**，只能通过"添加实例 → 文件夹 / 压缩包导入"把
  实例搬进来。

## 18. 其它

- **单开与唤回**：运行中的启动器把自己的 IPC 端口写进运行目录的 `temp`；重复启动的实例读到端口就
  通过 `mml-ipc` 通知它 —— 无参数请求显示主窗口，有参数把参数转过去，然后自己退出。

## 19. 未接线 / 半成品

分四类。前两类是"用户点得到但功能不生效"或"内核写好了但没有入口"，属于真正的缺口。

### 19.1 界面上有，但功能不生效

1. **游戏统计的记录侧**：**已补上** —— `game_count::init` 在 `lib.rs` 的 `mml_core::load` 之后调用，
   `launch_done` / `launch_error` / `game_close` 接在 `windows/main/launch.rs`，退出时 `stop()` 落盘，
   见 [§15](#15-游戏统计)。
2. **实例的"游戏内语言"不生效**：界面把选择写进实例的 `lang`，但启动时 `GameLaunchArg.lang`
   仍固定为 `None`（`windows/main/launch.rs`），于是 `${user_properties}` 恒为 `{}`。
3. **材质包启用 / 禁用写错文件**：见 [§20](#20-疑似缺陷待实机确认) 第 1 条（同时是缺陷）。
4. **模组依赖检测**：**已补上**（内核 `mods_dep_test` + 资源窗口的「依赖检测」），见 [§5.1](#51-模组)；
   本节余下的项仍是缺口。
5. **"检查整合包 mod"开关对普通实例无效**：判定条件要求实例是整合包类型。
6. **"预启动命令与游戏同时运行"没有实例级字段**，只能吃全局设置。

### 19.2 内核有实现，但没有入口

7. **联机 / 内网穿透**：`mml-net` 的 OpenFrp / SakuraFrp 接口（通道列表、通道配置、frpc 客户端下载）
   与 `mml-game` 的局域网联机都是完整的，但**没有任何窗口或按钮**；
   主界面"联机大厅"卡片目前点击只弹"功能开发中"。
8. **整合包升级**：**已补上** —— 实例详情区的「检查更新」走 `resource_modpack_check` / `resource_modpack_update`，
   差异计算在内核 `modpack/diff.rs`，见 [§6.4](#64-整合包更新)。
9. **单独"检查游戏文件"与"查看 / 复制本次启动命令"**：内核 `check_game_file`、`create_game_cmd`
   在 GUI 里没有调用点。
10. **账户多角色选择**：内核定义了选择回调，LittleSkin 与 Authlib 也会在多角色时调用它，
    但 GUI 两处都传 `None`，于是永远取第一个 / 按用户名匹配，没有选择弹窗。
11. **"清空全部账户"**：内核 `clear_auths` 存在，界面只有单条删除。
12. **单任务级下载控制**：内核有 `pause_task` / `resume_task` / `cancel_task`，
    但既没有 IPC 命令也没有按钮（界面只有全局三个动作）。下载窗口的文件头注释声称
    "每个任务可暂停 / 继续 / 停止"，与实现不符。
13. **资源下载无法取消**：添加资源那组没有 cancel 命令，进度卡只有"清除已完成"
    （DTO 里已有 `cancelled` 字段，只是没有入口）。
14. **导出格式 `MML` / `Zip`**：内核支持 6 种导出类型，GUI 只放行 4 种，另外两种只被测试使用。
15. **导出不能"排除文件"**：`ExportArg.unselect` 恒为空，前端也只有勾选没有排除。
16. **收藏的"安装选中"**：源码里明写本轮未实现。
17. **服务器包检查**：`server_pack_check` 被整段注释成空实现，服务器包只能在启动那一刻检查。
18. **内核死能力**（有实现、无任何入口）：`SaveObj::export`（导出存档）、
    `SaveObj::open_world_seed`（跳种子网站）、`names::OPTIFINE_FILE`。
19. **`settings_get_cache_path`**：命令已生成到前端，但前端全仓没有调用。

另：**崩溃分析**（`mml-analysis`）已接入日志窗口：打开历史日志 / 崩溃报告时自动分析，
按规则给出缺前置、依赖版本、加载器混装、Mixin、OOM、渲染、看门狗、维度等结论与可疑模组；
JVM 致命错误日志暂不分析。

### 19.3 数据与显示上的小缺口

20. 统计 DTO 里的"成功 / 失败启动次数"前端从不显示；内核 `CountObj.launch_logs` 后端也不读。
21. 主界面 `ActionId` 里的 `"export"` 没有实现分支，会落到"功能开发中"兜底（真正导出走另一个入口）。
22. `InstanceLogPanel.vue` 是死组件（全仓无引用），看日志走独立日志窗口。
23. 模组分组 / 备注类命令（`group_remove` / `order_set` / `collapsed_set` / `group_set` / `note_set`）
    返回 `()` 且实例解析失败时直接 `return`，前端拿不到错误（同组的 `add` / `rename` 会返回 `Err`）。
24. 整合包清单里的**可选文件**没有处理：CurseForge 的 `required` 字段存在但被忽略，`files` 全量下载，
    界面上也没有"选装哪些"。

### 19.4 注释 / 文案与实现不一致（写文档时最容易踩）

25. 帮助页 FAQ 仍写"当前版本为离线模式启动，正版与第三方登录将在后续版本支持"，
    而实际六种账户类型（含微软 OAuth 设备码）都已实现。
26. `DownloadWindow.vue` 注释称"每个任务可暂停 / 继续 / 停止"（实际只有全局按钮）。
27. `useSettingsJava.ts` 注释称 Java 列表按"JDK / JRE"分组，实际分组键是 `java -version` 的第一个词
    （发行方 / 实现名），**内核并不判断 JDK 还是 JRE**。
28. `useModGroups.ts` 注释称分组"默认全展开"，后端未写过时默认把三个状态分组当**收起**。
29. `settings/search.ts` 把"全屏 / 宽度 / 高度"列成三个可搜索项，界面上其实是一个分辨率下拉。
30. `lib/api.ts` 里"实例数据是占位的"一处注释已过时（实现是真的）。

## 20. 疑似缺陷（待实机确认）

1. **材质包启用 / 禁用走错文件，且原版实例会 panic**（已静态核实到代码路径，未实机复现）：
   - 列表判定与启用 / 禁用用的是 `InstanceSettingObj::get_options` / `save_options`
     （`mml-core/mml-game/src/game_resourcepacks.rs` 的列表 / 启用 / 禁用三处），而这两个方法读写的是
     `self.get_optifine_file()`（`game_options.rs`）——即
     `libraries/optifine/installer/OptiFine-<版本>-<加载器版本>.jar`，**不是游戏读的 `options.txt`**。
   - `get_optifine_file()` 内部对 `loader_version` 做 `unwrap()`：实例的 `LoaderVersion` 为空时
     （原版实例，或在详情里把加载器切成原版后）**直接 panic**；release 构建 `panic = "abort"`，
     后果是进程终止。debug 下表现为该命令失败。
   - 同一条链路上，正确的那一对是 `get_minecraft_options` / `save_minecraft_options`（光影用的就是它，
     所以光影切换是好的）。
   - 自查方法：原版实例打开"资源管理 → 材质包"，看是否崩 / 报错；再看
     `libraries/optifine/installer/` 下是否多出一个文本内容的 `OptiFine-*.jar`，
     以及 `options.txt` 的 `resourcePacks` 是否变化。
2. **Modrinth 无文件版本可能 panic**：取文件用 `unwrap_or(&obj.files[0])`，
   而调用点先于空表兜底，注释声称"不会 panic"并不成立。
3. **下载整合包遇到同实例名时的确认链路可疑**（未验证）：确认事件按 kind `"add"` 取模型、
   却发给"下载整合包"窗口，而监听方只有添加实例窗口 —— 可能表现为任务卡住或以取消收尾。
   自查：装一个与已有实例同名的整合包。
4. 收藏星标只按项目 ID 匹配、不看来源，跨源同 ID 会互相影响（概率极低）。
5. 数据包"未登记进 `level.dat` 两个列表即视为已启用"的口径未与游戏实际行为对账。
6. 存档备份索引按**存档名**存、按**目录名**反查：存档改名后旧备份是否仍显示，未实测。
